What the database proved

Historical data and explicit refresh

Two sensors × seven days produced 20,160 original rows and 336 hourly groups. A late reading and an old correction left exactly two materialized buckets stale. Refresh repaired both; average, minimum, maximum and count all matched raw SQL truth.

Fresh data beyond the watermark

Real-time mode enabled with materialized_only=false. A new reading at 2026-10-08 00:10 UTC appeared without another refresh: average/min/max 30 °C, count 1. The actual backing materialization still contained zero rows for that bucket.

An hourly refresh policy is configured with a 30-day start offset and 1-hour end offset. Background policy execution is not claimed. Late historical data still needs refresh; the raw real-time tail handles data newer than the watermark.

Measured query plans

Before the real-time tail phase, both queries returned the same 336 rows over the same seven-day window. Actual EXPLAIN (ANALYZE, BUFFERS) execution times: raw aggregation 3.574 ms; materialized CAGG read 0.085 ms.

One small local run with warm-cache effects; these observations are not a general speed guarantee or a benchmark of the final real-time union.
